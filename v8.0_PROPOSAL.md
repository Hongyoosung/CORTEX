## Executive Summary

v8.0 addresses architectural redundancy in v7.0 where both MCTS and RL select similar high-level decisions (Mission Type ≈ Strategy Type). The new design shifts RL from **strategic decision making** to **tactical parameter control**, creating a clearer hierarchical separation while leveraging proven EQS spatial reasoning:

**v7.0 (Current):**
```
MCTS (Strategic) → Assigns Missions [Assault, Defend, Support, Retreat]
   ↓
RL (Tactical?) → Selects Strategies [Assault, Defend, Support, Retreat]  ❌ REDUNDANT
   ↓
Rules (Execution) → Executes via EQS + NavMesh
```

**v8.0 (Approved):**
```
MCTS (Strategic) → Assigns Strategies [Assault, Defend, Support, Retreat]
   ↓
RL (Tactical) → Outputs Tactical Parameters [Aggression, Cover, Spread, Risk]  ✅ UNIQUE ROLE
   ↓
EQS (Execution) → Uses parameters as query weights + NavMesh movement
   ↓
Rules (Combat) → Auto-targeting + Auto-firing (v8.5: Learned targeting)
```

**Key Advantages:**
- Lower risk: Leverages proven EQS spatial reasoning
- Faster training: 4 continuous parameters easier than discrete movement
- Graceful degradation: Random parameters still produce valid EQS movement
- Clear path to v8.5: Add learned targeting once tactical control converges

## Problem Statement

### Current v7.0 Limitations

1. **Architectural Redundancy:**
   - Mission types and Strategy types are 90% identical
   - RL has limited agency (usually just follows mission type)
   - Two layers making essentially the same decision

2. **Training Inefficiency:**
   - RL learns high-level decisions that MCTS could handle
   - Strategy selection is simple (4 discrete choices) - underutilizes neural network capacity
   - Little emergent behavior (strategies map directly to positions)

3. **Scalability Issues:**
   - EQS queries become bottleneck at scale (50v50 scenarios)
   - Spatial reasoning handled by EQS, not by RL
   - RL doesn't learn tactical movement patterns

### Example of Redundancy

```cpp
// MCTS assigns mission
Mission.Type = EMissionType::Assault;  // "Go attack Point A"

// RL selects strategy (almost always matches mission)
Strategy = EStrategyType::Assault;     // "I'll attack aggressively"

// Rules execute (deterministic)
Position = ETacticalPosition::ForwardCover;  // Always maps Assault → ForwardCover
```

**Result:** RL adds minimal value beyond the MCTS assignment.

## Proposed v8.0 Architecture

### 1. Hierarchical Separation

#### Layer 1: MCTS (Strategic Decision)
**Responsibility:** Team-level strategy assignment
**Frequency:** Async, every 1.5s
**Output:** Strategy + Target Objective for each agent

```cpp
struct FStrategyAssignment
{
    AActor* Agent;
    EStrategyType Strategy;        // Assault, Defend, Support, Retreat
    AObjectiveActor* TargetObjective;  // Which objective to focus on
    int32 Priority;                // Strategy priority (0-10)
};
```

**Example MCTS Assignments:**
```cpp
// 4v4 scenario: Enemy base at Point A, friendly base at Point B
Agent1 → Strategy: Assault,  Target: EnemyBase (Point A)
Agent2 → Strategy: Assault,  Target: EnemyBase (Point A)
Agent3 → Strategy: Defend,   Target: FriendlyBase (Point B)
Agent4 → Strategy: Support,  Target: Agent1 (assist assault)
```

#### Layer 2: RL (Tactical Parameter Control)
**Responsibility:** Modulate EQS behavior via tactical parameters
**Frequency:** 2-5 Hz (event-driven on strategy change or periodic)
**Input:** Observation (68 features) + Assigned Strategy (embedded)
**Output:** 4 continuous tactical parameters [0, 1]

```cpp
// v8.0 Action Space: Tactical Parameters
struct FTacticalParameters
{
    float Aggression;        // 0.0 = passive, 1.0 = aggressive
    float CoverPreference;   // 0.0 = ignore cover, 1.0 = prioritize cover
    float SpreadDistance;    // 0.0 = tight formation, 1.0 = spread out
    float RiskTolerance;     // 0.0 = retreat early, 1.0 = fight to death
};
```

**Action Space Properties:**
- **Size:** 4 continuous outputs in [0, 1] (vs 4 discrete in v7.0)
- **Control Frequency:** 2-5 Hz (vs event-driven in v7.0)
- **Execution:** Modulates EQS query weights (vs direct strategy selection in v7.0)

#### Layer 3: EQS (Spatial Reasoning & Movement)
**Responsibility:** Tactical position selection using RL-modulated weights
**Frequency:** 2-5 Hz (synchronized with RL parameter updates)
**Logic:** Environmental Query System with RL-controlled weights

```cpp
// EQS query weights modulated by RL tactical parameters
void RunEQSQuery_v8(FTacticalParameters Params)
{
    FEnvQueryRequest QueryReq = FEnvQueryRequest(TacticalPositionQuery);

    // RL-controlled weight modulation
    QueryReq.SetFloatParam("AggressionWeight", Params.Aggression);
    QueryReq.SetFloatParam("CoverWeight", Params.CoverPreference);
    QueryReq.SetFloatParam("FormationWeight", 1.0f - Params.SpreadDistance);
    QueryReq.SetFloatParam("RiskThreshold", Params.RiskTolerance);

    // Execute EQS (proven spatial reasoning preserved)
    QueryReq.Execute(EEnvQueryRunMode::SingleResult, this,
                     &UFollowerAgentComponent::OnEQSQueryFinished);
}
```

#### Layer 4: Rules (Combat Execution)
**Responsibility:** Automatic targeting and firing
**Frequency:** Every tick (60 Hz)
**Logic:** Script-based, no learning (v8.5: learned targeting)

```cpp
void AutoTargetAndFire()
{
    // Priority: Closest enemy in LOS
    TArray<AActor*> Enemies = PerceptionComp->GetDetectedEnemies();
    AActor* Target = GetClosestEnemyInLOS(Enemies);

    if (Target)
    {
        AIController->SetFocus(Target);  // Auto-aim
        WeaponComp->Fire();              // Auto-fire if has LOS
    }
}
```

### Auto-Combat Design Decision

**Rationale:** v8.0 focuses on validating the MCTS+RL strategic hierarchy, not maximizing combat realism. Auto-targeting reduces learning complexity while allowing measurement of strategic effectiveness.

**Supporting Evidence:**

1. **Positioning Dominance Hypothesis**: In tactical shooters, positioning (cover, flanking, high ground) typically accounts for 70-80% of combat effectiveness vs aiming skill (20-30%)

2. **Complexity Budget**: Learning 9-action movement + 4 strategies is already 2.5× more complex than v7.0. Adding targeting would increase to 4-5× (movement × targeting × strategy combinations)

3. **Incremental Path**: v8.0 establishes movement foundation, v8.5 can add learned targeting once movement converges

**Validation Plan (Week 1):**
- Analyze v7.0 combat logs to measure win rate correlation with:
  - Positioning metrics: cover usage rate, flanking angle, distance to objective
  - Accuracy metrics: hit rate, headshot rate, damage per shot
- **Acceptance Criteria**: If positioning explains >70% of variance in win rate → auto-combat justified
- Document findings in v8.0 combat analysis report

**Future Extension (v8.5):**
- If positioning <70% predictive → add learned targeting to action space
- Possible action space: 9 movement × 5 aim offsets (center, up/down/left/right) = 45 actions
- Defer to v8.5 to avoid scope creep in v8.0

## 2. Unified Reward System with Strategy-Specific Weights

**Key Innovation:** Single reward calculator with strategy-specific weight profiles, ensuring maintainability and debuggability.

### Unified Reward Calculator Architecture

```python
class StrategyRewardCalculator:
    """
    Single source of truth for reward computation.
    Strategy-specific behavior emerges from weight profiles, not code duplication.
    """

    def __init__(self, strategy_type: EStrategyType):
        self.weights = REWARD_WEIGHTS[strategy_type]

    def calculate(self, state: AgentState) -> float:
        """
        Computes total reward as weighted sum of reward components.
        All strategies use same components, different weights.
        """
        reward = 0.0

        # Component 1: Objective Progress
        reward += self.weights['objective_progress'] * self._objective_reward(state)

        # Component 2: Combat Effectiveness
        reward += self.weights['combat_effectiveness'] * self._combat_reward(state)

        # Component 3: Survival
        reward += self.weights['survival'] * self._survival_reward(state)

        # Component 4: Cover Usage
        reward += self.weights['cover_usage'] * self._cover_reward(state)

        # Component 5: Team Coordination
        reward += self.weights['team_coordination'] * self._coordination_reward(state)

        return reward

    # ===== Reward Component Implementations (Strategy-Agnostic) =====

    def _objective_reward(self, state: AgentState) -> float:
        """Progress toward assigned objective (strategy determines weight)"""
        if state.distance_to_objective < state.last_distance_to_objective:
            return 0.1  # Moving closer
        return 0.0

    def _combat_reward(self, state: AgentState) -> float:
        """Combat effectiveness (kills, damage dealt)"""
        reward = 0.0
        if state.dealt_damage:
            reward += state.damage_amount / 10.0
        if state.killed_enemy:
            reward += 10.0  # Base kill reward (scaled by weight)
        return reward

    def _survival_reward(self, state: AgentState) -> float:
        """Survival/death penalty"""
        if state.died:
            return -10.0  # Base death penalty (scaled by weight)
        return 0.0

    def _cover_reward(self, state: AgentState) -> float:
        """Cover usage and tactical positioning"""
        if state.in_cover:
            return 0.1  # Continuous cover bonus
        return 0.0

    def _coordination_reward(self, state: AgentState) -> float:
        """Team coordination (proximity to allies, formation)"""
        reward = 0.0
        if state.ally_state:
            distance = get_distance(state.position, state.ally_state.position)
            if 200 < distance < 800:  # Optimal support range
                reward += 0.1
        return reward
```

### Strategy-Specific Weight Profiles

```python
# Single source of truth for reward tuning
REWARD_WEIGHTS = {
    'Assault': {
        'objective_progress':     1.0,   # High: push toward objective
        'combat_effectiveness':   0.8,   # High: engage enemies
        'survival':              0.6,   # Medium: acceptable risk
        'cover_usage':           0.3,   # Low: use cover but don't camp
        'team_coordination':     0.4,   # Medium: loose formation
    },

    'Defend': {
        'objective_progress':     0.2,   # Low: stay near objective (inverted)
        'combat_effectiveness':   0.6,   # Medium: suppress threats
        'survival':              1.0,   # High: must survive to hold position
        'cover_usage':           0.9,   # High: maximize cover usage
        'team_coordination':     0.5,   # Medium: defensive formation
    },

    'Support': {
        'objective_progress':     0.5,   # Medium: follow ally's objective
        'combat_effectiveness':   0.4,   # Medium-low: assist, don't solo
        'survival':              0.7,   # Medium-high: stay alive to support
        'cover_usage':           0.5,   # Medium: balanced positioning
        'team_coordination':     1.0,   # High: stick with ally
    },

    'Retreat': {
        'objective_progress':     0.8,   # High: reach safe zone
        'combat_effectiveness':   0.0,   # None: avoid combat entirely
        'survival':              1.2,   # Highest: survival paramount
        'cover_usage':           0.7,   # High: use cover while retreating
        'team_coordination':     0.3,   # Low: self-preservation priority
    },
}
```

### Expected Learned Behaviors

**Assault** (Aggressive Advance):
- High objective progress weight → learns to move toward enemy positions
- High combat effectiveness weight → engages enemies actively
- Medium survival weight → accepts moderate risk for progress
- Low cover usage weight → uses cover tactically but doesn't camp

**Defend** (Position Holding):
- Low objective progress weight → stays near assigned position
- Medium combat effectiveness weight → suppresses approaching enemies
- High survival weight → minimizes risk, maximizes longevity
- High cover usage weight → maximizes cover usage for defensive stance

**Support** (Ally Protection):
- Medium objective progress weight → follows ally's objective
- Medium-low combat effectiveness → assists rather than solo engages
- High team coordination weight → maintains proximity to ally
- Balanced cover/survival → protects ally while staying alive

**Retreat** (Disengagement):
- High objective progress weight → moves toward safe zone
- Zero combat effectiveness → avoids all combat
- Highest survival weight → prioritizes survival above all
- High cover usage weight → uses cover aggressively while retreating

### Advantages Over Separate Functions

1. **Maintainability**: Single codebase, tune via weight profiles
2. **Debuggability**: TensorBoard can visualize component contributions
3. **Experimentation**: Easy A/B testing of weight configurations
4. **Consistency**: All strategies use same reward logic, no duplicate code

## 3. Implementation Details

### Network Architecture

**Input:** 68 + 4 = 72 features
- 68 features: Existing observation (agent state, enemies, cover, allies)
- 4 features: Assigned strategy (one-hot encoded: Assault, Defend, Support, Retreat)

**Network:**
```
[72] → FC(128, ReLU) → FC(128, ReLU) → FC(64, ReLU)
                                           ↓
                                 ┌─────────────────┐
                                 │                 │
                          Policy Head(4, Sigmoid)  Critic Head(1)
                          Tactical Parameters      State Value
```

**Output:**
- Policy: 4 continuous values in [0, 1]
  - Output[0]: Aggression
  - Output[1]: CoverPreference
  - Output[2]: SpreadDistance
  - Output[3]: RiskTolerance
- Value: Scalar value estimate (for PPO/A2C)

### Architectural Enforcement of Strategy Differentiation

**CRITICAL ADDITION (2026-01-14):** After technical review, an architectural safeguard has been added to guarantee strategy-specific behavior differentiation.

#### Problem: Strategy Input May Be Ignored

The original design encodes strategy as 4 out of 72 input features (5.5%). Risk: The network might learn to ignore strategy input if environmental observations are more predictive:

```python
# Example: Low HP agent with Assault strategy
observation = [position, HP=0.1, enemies=3, ..., [1,0,0,0]]  # 68 + 4 features
# Network might learn: "HP < 0.2 → always retreat, ignore strategy"
# Result: Assault and Defend produce similar outputs
```

**Consequence:** Without architectural enforcement, strategy differentiation relies entirely on reward engineering, which is not guaranteed to succeed.

#### Solution: Separate Strategy-Specific Policy Heads

**Revised Architecture:**
```
Input: [68 observation features] + [4 strategy one-hot]
   ↓
Shared Feature Extractor:
   [68] → FC(128, ReLU) → FC(128, ReLU) → FC(64, ReLU)
   ↓
   Shared Features [64]
   ↓
   ┌─────────────┬──────────────┬──────────────┬──────────────┐
   ↓             ↓              ↓              ↓              ↓
Assault Head  Defend Head  Support Head  Retreat Head   Critic Head
FC(64→32)     FC(64→32)    FC(64→32)     FC(64→32)      FC(64→1)
FC(32→4)      FC(32→4)     FC(32→4)      FC(32→4)
Sigmoid       Sigmoid      Sigmoid       Sigmoid        Linear
   ↓             ↓              ↓              ↓              ↓
[4 params]    [4 params]   [4 params]    [4 params]    State Value
```

**Execution Logic:**
```python
# Python training code
shared_features = shared_network(observation[:68])  # [64]

# Route to strategy-specific head based on assigned strategy
if strategy == EStrategyType.Assault:
    tactical_params = assault_policy_head(shared_features)  # [4]
elif strategy == EStrategyType.Defend:
    tactical_params = defend_policy_head(shared_features)  # [4]
elif strategy == EStrategyType.Support:
    tactical_params = support_policy_head(shared_features)  # [4]
elif strategy == EStrategyType.Retreat:
    tactical_params = retreat_policy_head(shared_features)  # [4]

# Critic head is shared (value estimation independent of strategy)
state_value = critic_head(shared_features)  # [1]
```

#### Advantages

1. **Guaranteed Differentiation**: Each strategy has dedicated output layers - architecturally impossible to produce identical outputs
2. **Easier Debugging**: Can visualize each strategy's learned parameters independently
3. **Faster Convergence**: No competition between strategies for shared output weights
4. **Graceful Learning**: Even if reward weights are suboptimal, strategies will still differentiate

#### Parameter Cost

**Original Design:**
- Shared layers: 128×128 + 128×64 = 24,576 params
- Policy head: 64×4 = 256 params
- Critic head: 64×1 = 64 params
- **Total: ~24,896 params**

**Revised Design:**
- Shared layers: 24,576 params (unchanged)
- 4 strategy heads: 4 × (64×32 + 32×4) = 4 × 2,176 = 8,704 params
- Critic head: 64×1 = 64 params
- **Total: ~33,344 params (+34% increase)**

**Justification:** 8KB additional model size is negligible (ONNX model ~450 KB → ~458 KB). The architectural guarantee of differentiation is worth the modest parameter increase.

#### Expected Behavioral Impact

With separate heads, each strategy can learn distinct parameter profiles:

```python
# Example learned outputs for same observation
obs = [position=(500,500), HP=0.7, enemies_visible=1, in_cover=False, ...]

assault_head(obs)  → [Aggression=0.85, CoverPref=0.30, Spread=0.60, Risk=0.70]
defend_head(obs)   → [Aggression=0.20, CoverPref=0.90, Spread=0.40, Risk=0.25]
support_head(obs)  → [Aggression=0.45, CoverPref=0.55, Spread=0.25, Risk=0.50]
retreat_head(obs)  → [Aggression=0.10, CoverPref=0.75, Spread=0.80, Risk=0.15]
```

**Without** separate heads: Risk of convergence to similar outputs (e.g., all ~0.5)
**With** separate heads: Guaranteed differentiation through independent learning

### Combat Control Extension (2026-01-14)

**CRITICAL ADDITION:** After review, minimal combat control has been added to prevent over-simplification of combat effectiveness.

#### Problem: Auto-Combat May Oversimplify

Original v8.0 design: "Always shoot closest enemy in LOS"

**Risk:** Combat effectiveness may depend heavily on target selection:
- Example: Shooting low-HP enemy vs closest enemy can swing fights
- The "positioning dominates 70-80%" hypothesis is unvalidated

#### Solution: Learned Target Priority + Engagement Style

**Extended Action Space:**
```cpp
// Movement: 4 continuous tactical parameters (unchanged)
struct FTacticalParameters {
    float Aggression;        // [0,1] - modulates EQS weights
    float CoverPreference;   // [0,1] - modulates EQS weights
    float SpreadDistance;    // [0,1] - modulates EQS weights
    float RiskTolerance;     // [0,1] - modulates EQS weights
};

// Combat: 2 discrete learned choices (NEW)
struct FCombatParameters {
    ETargetPriority Priority;    // 3 choices: Closest, LowestHP, MostThreatening
    EEngagementStyle Style;      // 3 choices: Aggressive, Suppressive, HoldFire
};
```

**Network Architecture Extension:**
```
Shared Features [64]
   ↓
   ┌──────────────┬────────────────┬────────────────┐
   ↓              ↓                ↓                ↓
Strategy Head  Target Priority  Engagement Style  Critic
(4 cont.)      (3-way softmax)  (3-way softmax)   (value)
```

**Total Action Space:**
- 4 continuous tactical parameters (movement)
- 3 target priorities (combat)
- 3 engagement styles (combat)
- **Complexity: 4 continuous + 2 discrete (3×3 = 9 combat states)**

**Combat Execution:**
```cpp
void UFollowerAgentComponent::ExecuteCombat(FCombatParameters Combat)
{
    TArray<AActor*> Enemies = PerceptionComp->GetDetectedEnemies();

    // RL-controlled target selection
    AActor* Target = nullptr;
    switch (Combat.Priority)
    {
        case ETargetPriority::Closest:
            Target = GetClosestEnemy(Enemies);
            break;
        case ETargetPriority::LowestHP:
            Target = GetLowestHPEnemy(Enemies);
            break;
        case ETargetPriority::MostThreatening:
            Target = GetMostThreateningEnemy(Enemies);  // Highest DPS or closest
            break;
    }

    if (!Target) return;

    // RL-controlled engagement style
    AIController->SetFocus(Target);  // Auto-aim (kept from v8.0)

    switch (Combat.Style)
    {
        case EEngagementStyle::Aggressive:
            WeaponComp->SetFireMode(EFireMode::FullAuto);
            WeaponComp->Fire();
            break;
        case EEngagementStyle::Suppressive:
            WeaponComp->SetFireMode(EFireMode::Burst);
            WeaponComp->Fire();  // Fire in bursts to conserve ammo
            break;
        case EEngagementStyle::HoldFire:
            // Track target but don't fire (avoid revealing position)
            break;
    }
}
```

**Advantages:**
- Still uses auto-aim (no aiming skill required - keeps v8.0 simplicity)
- Adds tactical depth to combat (who to shoot, when to shoot)
- Minimal complexity increase (9 discrete combat states vs pure auto-combat)
- Validates "positioning dominance" hypothesis through experimentation, not assumption

**Reward Integration:**
```python
def _combat_reward(self, state: AgentState) -> float:
    reward = 0.0

    # Target priority rewards
    if state.killed_enemy:
        if state.target_was_lowest_hp:
            reward += 12.0  # Bonus for efficient target selection
        else:
            reward += 10.0  # Base kill reward

    # Engagement style rewards
    if state.engagement_style == 'HoldFire' and state.in_stealth:
        reward += 0.5  # Reward stealthy positioning

    if state.engagement_style == 'Suppressive' and state.ammo_efficiency > 0.3:
        reward += 0.3  # Reward ammo conservation

    return reward
```

### EQS Parameter Modulation

```cpp
// STTask_ExecuteTacticalMovement_v8.cpp
void FSTTask_ExecuteTacticalMovement_v8::ApplyTacticalParameters(
    FStateTreeExecutionContext& Context,
    FTacticalParameters Params) const
{
    FInstanceDataType& InstanceData = Context.GetInstanceData(*this);
    UFollowerAgentComponent* AgentComp = InstanceData.AgentComponent;

    // Configure EQS query based on RL-provided tactical parameters
    FEnvQueryRequest QueryReq = FEnvQueryRequest(InstanceData.TacticalPositionQuery);

    // Distance to enemy scoring (aggression)
    float MinDistanceToEnemy = FMath::Lerp(1000.0f, 200.0f, Params.Aggression);  // 10m to 2m
    QueryReq.SetFloatParam("MinDistanceToEnemy", MinDistanceToEnemy);
    QueryReq.SetFloatParam("AggressionWeight", Params.Aggression * 2.0f);  // 0-2 range

    // Cover preference
    QueryReq.SetFloatParam("CoverWeight", Params.CoverPreference * 5.0f);  // 0-5 range
    QueryReq.SetFloatParam("ExposureWeight", (1.0f - Params.CoverPreference) * 3.0f);

    // Formation spread
    float IdealSpreadDistance = FMath::Lerp(200.0f, 1000.0f, Params.SpreadDistance);  // 2m to 10m
    QueryReq.SetFloatParam("FormationSpread", IdealSpreadDistance);
    QueryReq.SetFloatParam("FormationWeight", 3.0f);

    // Execute EQS query
    QueryReq.Execute(EEnvQueryRunMode::SingleResult, AgentComp,
                     &UFollowerAgentComponent::OnTacticalPositionFound);

    // Store risk tolerance for retreat logic (used outside EQS)
    AgentComp->SetRiskTolerance(Params.RiskTolerance);
}

// Called when EQS finds optimal position
void UFollowerAgentComponent::OnTacticalPositionFound(TSharedPtr<FEnvQueryResult> Result)
{
    if (Result->IsSuccessful())
    {
        FVector TargetPosition = Result->GetItemAsLocation(0);

        // Issue movement to EQS-selected position
        FAIMoveRequest MoveReq(TargetPosition);
        MoveReq.SetAcceptanceRadius(100.0f);  // 1m acceptance
        MoveReq.SetUsePathfinding(true);      // Use NavMesh pathfinding

        AIController->MoveTo(MoveReq);
    }
}
```

### Control Loop

```cpp
// FollowerAgentComponent_v8.cpp
void UFollowerAgentComponent::TickComponent(float DeltaTime, ...)
{
    // v8.0: Event-driven or periodic (2-5 Hz) parameter updates
    TicksSinceLastParameterUpdate++;
    if (TicksSinceLastParameterUpdate < 12)  // 60 FPS / 5 Hz = 12 ticks
    {
        // Continue executing current EQS movement, don't query new parameters yet
        AutoTargetAndFire();  // Combat runs every tick
        return;
    }

    TicksSinceLastParameterUpdate = 0;

    // Build observation
    FObservationElement Obs = BuildLocalObservation();

    // Get assigned strategy from MCTS (via TeamLeader)
    EStrategyType AssignedStrategy = GetAssignedStrategy();

    // Query RL policy for tactical parameters (4 continuous outputs)
    FTacticalParameters Params = TacticalPolicy->GetTacticalParameters(Obs, AssignedStrategy);

    // Apply parameters to EQS query
    ApplyTacticalParameters(Params);

    // Combat is handled separately (auto-targeting)
    AutoTargetAndFire();
}
```

## 4. Training Considerations

### Curriculum Learning

Progressive difficulty increase to aid convergence:

**Phase 1: Single Strategy Training (Episodes 0-1000)**
```python
# All agents use same strategy, learn basic movement
# Example: All agents assigned Assault strategy
# Learn: Move toward objective, avoid obstacles
```

**Phase 2: Mixed Strategy Training (Episodes 1000-3000)**
```python
# MCTS explores simple 2-2 splits
# Example: 2 agents Assault, 2 agents Defend
# Learn: Different movement patterns per strategy
```

**Phase 3: Dynamic Strategy Assignment (Episodes 3000+)**
```python
# MCTS freely assigns strategies based on game state
# Example: 3 Assault, 1 Support (dynamic based on health)
# Learn: Adaptive tactics, strategy coordination
```

### Reward Shaping

**Dense Intermediate Rewards:**
```python
# v8.0 requires dense rewards (actions are low-level, sparse mission completion too far away)
reward_per_step = 0.0

# Progress rewards (every step)
reward_per_step += proximity_reward(strategy)  # Strategy-specific
reward_per_step += cover_reward(strategy)      # Strategy-specific
reward_per_step += formation_reward(strategy)  # Team coordination

# Combat rewards (event-based)
reward_per_step += damage_reward(strategy)     # On damage event
reward_per_step += kill_reward(strategy)       # On kill event
reward_per_step += death_penalty(strategy)     # On death event

# Terminal rewards (episode end)
if episode_complete:
    reward_per_step += objective_completion_reward(team_performance)
```

### Exploration Strategy

**Epsilon-Greedy with Strategy-Aware Decay:**
```python
def get_epsilon(episode, strategy):
    # Assault and Support: Explore more (risky strategies)
    if strategy in [EStrategyType.Assault, EStrategyType.Support]:
        base_epsilon = 0.3
        decay_rate = 0.9995
    # Defend and Retreat: Explore less (conservative strategies)
    else:
        base_epsilon = 0.2
        decay_rate = 0.999

    return max(0.05, base_epsilon * (decay_rate ** episode))
```
