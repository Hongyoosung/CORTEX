# v9.0 Migration Guide: Policy Update Barrier

## Overview

v9.0 fixes the episode desync issue caused by async policy updates.

**Problem:** Python updates policy (10-30s) while UE5 continues running → partial episodes → corrupted training data

**Solution:** Pause gRPC thread during policy updates → clean episode boundaries → stable training

## What Changed

### New Features
1. **Pause/Resume Mechanism** (`sbdapm_env_async.py`)
   - Added `pause()` and `resume()` methods
   - gRPC thread respects pause flag
   - Prevents UE5 advancement during training

2. **Policy Update Callback** (`policy_update_pause_callback.py`)
   - Automatically pauses before training
   - Automatically resumes after training
   - Integrated with RLlib lifecycle

### Removed Legacy Code
1. **Observation-based reset detection** (v8.9)
   - Health tracking removed
   - Reset detection queue removed
   - Warning threshold logic removed

2. **Episode tracking band-aids** (v8.9.2)
   - `processed_episode_completions` set removed
   - Duplicate increment prevention removed
   - Simplified episode counter logic

3. **Excessive logging**
   - Removed diagnostic prints
   - Streamlined version messages

## Migration Steps

### 1. Update Training Script

**Old (v8.9.2):**
```python
config = config.callbacks(EpisodeLoggerCallback)
```

**New (v9.0):**
```python
from policy_update_pause_callback import PolicyUpdatePauseCallback
from ray.rllib.algorithms.callbacks import MultiCallbacks

config = config.callbacks(MultiCallbacks([
    EpisodeLoggerCallback,
    PolicyUpdatePauseCallback  # ← Add this
]))
```

### 2. No Environment Changes Needed

The environment (`sbdapm_env_async.py`) is automatically compatible.
- v9.0 added `pause()`/`resume()` methods
- Callback will use them automatically
- Old code will still work (pause/resume are optional)

### 3. Update UE5 (No changes required)

UE5 doesn't need any changes. The pause happens on Python's side by stopping the gRPC polling thread.

### Troubleshooting

**Issue:** No PAUSED/RESUMED messages
```bash

python -c "

print(config.callbacks_class)
"
# Should output: <class 'ray.rllib.algorithms.callbacks.MultiCallbacks'>
```

**Issue:** Episode lengths still variable
- Verify callback is registered (see above)
- Check that all workers use the same config
- Ensure UE5 MaxEpisodeDuration matches Python expectations

**Issue:** Training seems slower
- Expected: ~15% overhead (10-30s pause per 60-120s iteration)
- Acceptable tradeoff for stable training data
- If overhead >30%, check network latency

## FAQ

**Q: Why 15% overhead?**
A: Policy updates take 10-30s, sample collection takes 60-120s. Pausing during updates adds idle time.

**Q: Can we avoid the overhead?**
A: Not without corrupting training data. Clean episodes > wall-clock speed.

**Q: Does this affect inference?**
A: No. Pause/resume is only active during training. Inference doesn't use callbacks.

**Q: What if UE5 needs to pause too?**
A: Currently unnecessary. Python-side pause is sufficient. Future enhancement if needed.
